# LiveCode Typer Portable 0.3.1

Rust-версия LiveCode Typer для Windows и macOS. Приложение работает поверх любых полей ввода: редактора кода, IDE, браузера, Блокнота и обычных текстовых файлов. После включения печати любую клавишу можно нажимать как сигнал для следующего символа из выбранного текста. Пробелы и переходы строк приложение отправляет само.

## Как пользоваться

1. Запустите `live-code-typer`.
2. В первый раз прочитайте короткую инструкцию в приложении. Вставьте в редактор код или любой текст. Длина текста ограничена доступной памятью; сервер комнаты принимает до 1 МБ на задание.
3. При необходимости добавьте фрагменты, переключайтесь между ними кнопками слева и закрепите важный фрагмент.
4. Включите печать кнопкой или горячей клавишей.
5. Перейдите в нужное текстовое поле и нажимайте любые буквы. Приложение подменяет сигнал клавиши следующим символом из текста. Символ `\n` отправляется как настоящий Enter.
6. Пауза и экстренная остановка доступны отдельными кнопками и сочетаниями.

На Windows первый запуск переносит фрагменты, положение печати, сочетания и настройки комнаты из `%AppData%\LiveCodeTyper\library.json` в `portable-data`. При первом запуске сервера туда же переносятся сохранённые задания, участники и история из `%AppData%\LiveCodeTyper\Server\room.json`. Оба исходных файла остаются без изменений.

Горячие клавиши по умолчанию:

| Действие | Сочетание |
| --- | --- |
| Печать / пауза | `Ctrl+Alt+Space` |
| Следующий фрагмент | `Ctrl+Alt+ArrowRight` |
| Предыдущий фрагмент | `Ctrl+Alt+ArrowLeft` |
| С начала | `Ctrl+Alt+R` |
| Закрепить / открепить | `Ctrl+Alt+L` |
| Экстренная остановка | `Ctrl+Alt+Escape` |

Сочетания меняются в окне **Горячие клавиши**: нажмите **Изменить**, нажмите новое сочетание и сохраните. Если сочетание занято или повторяет другую команду, приложение оставляет предыдущие привязки.

Закреплённый фрагмент нельзя редактировать или удалить. Назначенное из комнаты задание закрепляется автоматически и хранится отдельно от локальных фрагментов.

## Онлайн-комната

На компьютере, который будет ведущим, запустите сервер:

* В готовом архиве Windows запустите `Start-Room-Server.cmd`.
* В готовом архиве macOS запустите `Start-Room-Server.command`.
* Из исходников используйте команду ниже.

```powershell
cargo run --release --bin live-code-room-server
```

Сервер покажет готовые ссылки комнаты с кодом внутри. Откройте ссылку с IP ведущего и отправьте её участникам: на Windows и Mac её можно открыть в Safari, Chrome, Edge или другом браузере. Ведущий может скопировать приглашение из панели. Чтобы текст появился в редакторе участника, тот запускает настольное приложение, вставляет туда ту же ссылку в поле **Ссылка комнаты или адрес сервера** и вводит имя. Браузерная панель управляет заданиями, но сама не печатает в редактор.

Компьютеры должны быть в одной локальной сети или Wi-Fi. Если Windows спросит о брандмауэре, разрешите сервер только для частной сети. Если участник не может открыть ссылку, проверьте, что сервер продолжает работать, оба устройства в одной сети и используется ссылка с IP ведущего, а не `localhost`. Все участники имеют одинаковые права: каждый может добавлять задания, назначать их и отправлять выбранному человеку произвольный текст.

Сервер сохраняет задания, назначения и журнал рядом с системными данными приложения. Если рядом с исполняемым файлом есть `portable-data`, клиент и сервер используют эту общую папку для переносимых настроек и данных комнаты. Пока это HTTP-сервер для локальной сети; он не содержит TLS, учётных записей или защиты для публикации в открытом интернете. Запускайте его только в доверенной сети.

## Сборка

Нужен Rust stable и средства сборки для своей системы. На Windows установите Rust с MSVC Build Tools; на Mac установите Xcode Command Line Tools.

```sh
cargo build --release --bins
```

Команда собирает клиент `live-code-typer` и сервер `live-code-room-server` для текущей ОС. Для сборки под конкретную архитектуру сначала добавьте target:

```sh
# Windows x64
rustup target add x86_64-pc-windows-msvc
cargo build --release --target x86_64-pc-windows-msvc --bins

# macOS Apple Silicon
rustup target add aarch64-apple-darwin
cargo build --release --target aarch64-apple-darwin --bins

# macOS Intel
rustup target add x86_64-apple-darwin
cargo build --release --target x86_64-apple-darwin --bins
```

Для переносимого хранения создайте папку `portable-data`: в Windows рядом с `.exe`, а на macOS рядом с `.app` и сервером. Оставляйте её снаружи `.app` и переносите всю папку выпуска целиком. Если папки нет, настройки хранятся в стандартном каталоге пользователя.

На macOS системе нужно разрешить приложению **Универсальный доступ** и **Мониторинг ввода**. Сборки CI получают локальную ad-hoc-подпись, но не проходят notarization Apple; macOS может попросить отдельно подтвердить первый запуск. На Linux перехват зависит от графического сервера и прав ОС; сборка Linux не обещает работу в каждой среде Wayland.

Файл [build-portable.yml](.github/workflows/build-portable.yml) собирает Windows x64, macOS Intel и Apple Silicon на соответствующих системах и сохраняет архивы как GitHub Actions artifacts. После отправки проекта в GitHub их можно скачать на странице успешного запуска workflow.

## Проверка

Сквозные сценарии запускаются в PowerShell 7 на Windows с Microsoft Edge и Node.js:

```powershell
cargo build --bins
./verification/Verify-RustDesktop.ps1 `
  -AppPath ./target/debug/live-code-typer.exe `
  -ServerPath ./target/debug/live-code-room-server.exe
./verification/Verify-RustOnlineRoom.ps1 -ServerPath ./target/debug/live-code-room-server.exe
./verification/Verify-RustMigration.ps1 -AppPath ./target/debug/live-code-typer.exe
./verification/Verify-RustRoomMigration.ps1 -ServerPath ./target/debug/live-code-room-server.exe
```

Первый сценарий запускает приложение, сервер и настоящее тестовое окно: проверяет случайный ввод, пробел, Enter, изменение сочетания, сохранение после перезапуска и полный путь от сервера комнаты до печати назначенного текста настольным клиентом. Второй запускает сервер, проверяет API, постоянное хранение, вход браузера, создание и назначение задания, быструю отправку и адаптивность на узком и широком экране.
Третий без окна приложения переносит старый формат библиотеки и сверяет код с Unicode, позицию, закрепление, сочетания, настройки комнаты и сохранность исходного файла. Четвёртый переносит старую базу сервера, включая задания, участников, назначения и историю действий, также не меняя исходный файл.

Конечная модель критичного ядра печати проверяется TLC и перебирает все последовательности длиной до четырёх элементов из букв, пробелов и переносов строк:

```powershell
./formal/Verify-Model.ps1
```

Для собранного Windows-архива отдельно проверьте переносимый путь данных сервера:

```powershell
./verification/Verify-PortableServer.ps1 `
  -ServerPath ./dist/live-code-typer-windows-x64-v0.3.1/live-code-room-server.exe
```

Нужна Java 11 или новее. Модель проверяет границы курсора, соответствие напечатанного текста и блокировку закреплённого кода. Она дополняет E2E, но не заявляет формальное доказательство системного перехвата клавиатуры или графических интерфейсов ОС.
